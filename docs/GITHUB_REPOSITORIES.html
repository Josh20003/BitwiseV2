Branches and workflow

  • main is production. Code is deployed to the live cloud server (https://bitwise.live) using automated Docker Compose deployment scripts (bitwise-deploy/aws/deploy.sh).
  • new/features is the staging and integration branch. Feature and fix branches merge into it, where full integration testing is performed.
  • Feature branches (new_feature_ai, feature/refractored-lessons, new-feature-refactored-lesson) isolate individual curriculum refactorings, calculation algorithm improvements, and AI assistant prompt engineering.
  • Automated tests & quality gates: Strict TypeScript compilation verification (npx tsc -b) with 0 errors before merging; Prisma migration checks against live Supabase PostgreSQL.
  • Commit messages follow a house style: A descriptive prefix (feat:, fix:, refactor:, docs:) followed by a concise subject explaining what changed and why in plain English.
