1. Refactoring Evidence
Bitwise capstone, Deliverable 1: Working Software and Deployment. Status as of 18 October 2026.
1.1. Summary

Refactoring shows up in the project history as continuous, described commits rather than a single monolithic rewrite. In the Bitwise learning system, refactoring focused on three engineering priorities: (1) eliminating visualizer clutter in favor of interactive, high-retention practice challenges, (2) decoupling mathematical conversion and digital logic algorithms into modular backend services, and (3) migrating state management to TanStack router parameters and Supabase connection poolers. Larger restructurings progressed through dedicated feature branches, and every commit describes what changed and why in plain English.

1.4. Key Architecture Improvements Achieved

• Code Reduction: Over 1,200 lines of obsolete visualizer scaffolding, redundant icon imports (Layers, BookOpen, ArrowUp), and duplicated state containers were permanently removed.
• Type Safety: Refactoring ensured npx tsc -b compiles with 0 errors across all router parameters, API contracts, and interactive component props.
• Performance & UX: Component re-renders were minimized by localizing state variables (score, streak, qi) inside leaf challenge cards rather than top-level containers.
